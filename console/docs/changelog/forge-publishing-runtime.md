# Forge publishing runtime

The desktop History screen now has a real provider-publishing runtime rather than a queued toast. It discovers local GitHub CLI accounts, confirms the selected login is active, keeps only account ids and operating-system vault references, loads personal and organization owners from provider data with partial permissions, and makes the fork and copy-and-push routes visibly distinct. Typed `gh` and `git` calls run with `shell: false`, bounded deadlines, cleared inherited authentication variables, exact destination identity and push-URL verification through `git ls-remote`, atomic versioned state, reloadable account and publication receipts, direct device sign-in with surfaced user code and verification URL, cancellation, progress, and explicit re-authentication outcomes. GitLab remains an honest unavailable capability until its adapter exists. Runtime provider verification remains unrun.
