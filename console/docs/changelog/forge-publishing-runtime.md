# Forge publishing runtime

The desktop History screen now has a real provider-publishing runtime rather than a queued toast. It discovers local GitHub CLI accounts, confirms the selected login is active, proves `keyring` storage and refuses plaintext fallback, keeps only account ids and provider-supplied vault references, loads personal and organization owners from provider data with unknown organization capabilities until proven, and makes the fork and copy-and-push routes visibly distinct. Typed `gh` and `git` calls run with `shell: false`, per-request bounded deadlines, cleared inherited authentication variables, exact destination identity and effective push-URL verification through `git ls-remote`, atomic versioned state, reloadable account and publication receipts, direct device sign-in with surfaced user code and verification URL, cancellation, progress, and explicit re-authentication outcomes. The packaged contract still lacks an immutable approved public OAuth client id, so sign-in remains an explicit release blocker. GitLab remains an honest unavailable capability until its adapter exists. Runtime provider verification remains unrun.
