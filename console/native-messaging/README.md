# Native messaging ingress

The packaged host is the dedicated `Ding-PBX-Console-NativeMessagingHost.exe`, built by `build-native-host.ps1` through the supported MSVC path, with the supported MinGW fallback when MSVC is unavailable. The script records the executable SHA-256 and fails closed when no supported compiler or executable proof exists. It is submission-only. The browser manifest authenticates the allowlisted shipped extension id `dnpkplcgjmipnndmghkhljjoefjhidab`, the host repeats the exact 32-character id, and the desktop main process validates the complete handoff schema before opening the native destination picker or adding the handoff to the durable queue.

The host has no transfer command, snapshot, queue-read, credential, or file-write operation. It forwards one bounded JSON handoff over a random per-installation named pipe after proving the protected challenge, and returns only the desktop receipt. `Ding-PBX-Console-NativeIngressBroker.exe` owns that pipe with an explicit protected descriptor granting only the current user and `SYSTEM`, applies a two-slot cap, rejects incomplete frames by deadline, and emits a ready handshake before the desktop accepts ingress. Startup has a bounded deadline and the registration action settles only on ready, error, or unavailable. The desktop verifies the broker's effective owner, inheritance, identities, rule type, and full-control mask before ready. `register-native-host.ps1` resolves the absolute installed host and broker paths, records the challenge and pipe configuration under a protected per-user directory, and registers the manifest for Chrome and Edge, returning a compact typed JSON receipt.

The transfer process performs a second parent reparse inspection after directory creation and before opening its temporary file. The packaged native-messaging resource is the authenticated ingress boundary; the browser extension itself is not part of this Oak Kay.

`secure-temp-helper.cpp` contains the native directory-handle contract used by the Windows packaging lane: it opens the parent with `FILE_FLAG_OPEN_REPARSE_POINT` and no delete sharing, verifies `FILE_ATTRIBUTE_REPARSE_POINT`, and creates the child relative to that still-open handle through `NtCreateFile`. Its `--stream` and `--resume-stream` modes retain the safe child handle while the transfer manager streams new or resumed bytes, emit cumulative size and write acknowledgements only after `WriteFile` and `FlushFileBuffers`, and return a typed final receipt. The manager never creates a path and reopens it, and it reconciles the actual temporary size after a helper interruption before retaining a partial. Cancellation waits for helper close before bounded sharing-violation delete retry. It is compiled as the packaged `Ding-PBX-Console-SecureTempHelper.exe` by `build-native-host.ps1`. The build removes stale outputs, captures each compiler result independently, and refuses to hash until the host, broker, and helper are fresh regular files.
