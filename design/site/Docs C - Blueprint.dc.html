03

The control plane's safety model

Nothing the console does reaches a target through an open shell. Observation runs through an allowlist of 63 read-only CLI commands, each verified against Asterisk's own source rather than invented. Change runs through an allowlist of 41 writable configuration resources, reached only through ConfigTransaction / StructuredConfigPlanner:

backup→ stage→ validate→ apply→ post-read→ compare

Automatic rollback fires if the post-read doesn't match what was written. There is no free-text command execution and no way for the interface to construct an arbitrary shell invocation. Every destructive or write action passes one confirmation flow that calls the underlying action and reports its real outcome — including refusals — rather than announcing success unconditionally.

05

The bundled WSL runtime

The installer carries a complete Ubuntu 24.04 root filesystem, built from this exact repository commit, with Asterisk and every runtime library it needs already compiled and installed — verified by checking the closure of dynamic-library dependencies, not just a successful compile.

The console can create, verify, stop, and remove its own distribution, verifying success by asking the distribution for its actual Asterisk version rather than trusting a process exit code. It refuses to import over an existing distribution and refuses to remove one it did not create — both refusals exercised against a real Windows/WSL machine, not a scripted stand-in.

06

Build & installer scripts

Run from the repository root on Windows. Every script installs what it needs itself, reports honestly per phase, and never touches code signing.

download-dependencies.bat [/s]Fetches and digest-verifies every pinned dependency into a user-scoped, per-project cache. Idempotent — re-run is a no-op once warm.
build.bat [/s]Dependency fetch, npm ci, and a runnable copy of the console out of the checkout. /s runs unattended for CI or another agent.
build-installer.bat [/s]Builds the Windows installer through Squirrel.Windows — the same packaging path CI uses — and verifies Setup.exe, the RELEASES index, and the full .nupkg exist, are the right shape, and are unsigned as expected. Prints the SHA-256 of each output.
build-wsl-throwaway.batBuilds the Ubuntu root filesystem image bundled into the installer, by compiling this repository's own Asterisk source inside a container.

08

Roadmap — stated plainly

A survey against this checkout measured the console at roughly 12% of Asterisk's configurable surface. The control plane no longer limits this — writable resources went from 10 files to 41 and read-only commands from 23 to 63 — so each remaining gap needs only its screen and control bindings.

NO DESTINATION EXISTS YET
  • Access control rules (acl.conf) — the highest-value gap: SIP scanning is constant and toll fraud is the expensive failure
  • Sound prompt management — upload, audition, remove
  • TLS & certificates — transports, STIR/SHAKEN keys
  • Hardware trunks — analogue, T1/E1, PRI
  • Database / realtime backends, fax, channel event logging, call attestation, emergency location, phone provisioning, feature codes & parking, and more
EXISTS BUT PARTIAL
  • Security — edits no access rule or attestation certificate yet
  • Trunks — PJSIP only; no IAX2 or hardware
  • IVR — no dialplan application depth
  • Logger — level chips only; no rotation or queue log
  • Modules, call records, manager/REST, voicemail, codecs — each covers a fraction of its subsystem

One constraint governs all of it: nothing here has yet written to a live Asterisk beyond a disposable target. No mutation is called verified until an approved plan runs against a real exchange.

09

Security policy

Report vulnerabilities privately through the repository's Security tab — never through regular public issues. One vulnerability per advisory: separate reports keep CVEs, CWE values, severities, and affected versions cleanly attached to their fixes. Don't use the temporary-private-fork feature — such forks can't run the validation workflows; once an advisory is accepted you'll get instructions for submitting a fix.

For vulnerabilities in Asterisk itself, consult the upstream project's supported-versions and security pages at docs.asterisk.org.

Contributing

01Clone, then download-dependencies.bat /s at the root — or npm ci inside console/ for renderer-only work.
02npm test in console/ runs the full local suite described above.
03Never hand-edit console/app/renderer/src/generated/ — it's compiled from the checked-in design reference, and a drift test fails the build if the shipped renderer isn't byte-identical to a fresh compile. Change the design reference and recompile.
04ROADMAP.md and HANDOFF.md are the honest source of what is and isn't done — read them before proposing a feature.
05No sample or invented data may be reintroduced into the running application: an unread surface stays empty with a stated reason, and an unread cell renders as an em dash, never a placeholder value.
